# 0.1.0

_In development. Not yet released._

Querydown 0.1.0 is the first release that's published to crates.io and npm: the compiler as a Rust crate, a command line tool, and a JavaScript package built to WebAssembly, along with syntax highlighting and autocompletion for CodeMirror 6.

## How to get it

| Package | Install it with |
| -- | -- |
| The [command line tool](../../../docs/setup/cli.md) | `cargo install querydown-cli` |
| The [Rust crate](../../../docs/setup/rust.md) | `cargo add querydown` |
| The [JavaScript package](../../../docs/setup/javascript.md) | `npm install querydown-js` |
| The [CodeMirror package](../../../docs/setup/codemirror.md) | `npm install querydown-codemirror querydown-js` |

See [installation](../../../docs/setup/installation.md) for the details.

Querydown is still young. Until version 1.0, a release that changes the minor version (0.1 to 0.2, say) can break queries and code written for the one before. Its notes will say what changed and what to do about it.

## What's in it

- **The language**: conditions, result columns, sorting, grouping, paths through related tables, aggregates, window functions, pipelines, unions, definitions, and annotations. The [language](../../../docs/language.md) page describes all of it.
- **Built-in functions**: a modest set of scalar, aggregate, and window [functions](../../../docs/functions.md).
- **SQL dialects**: PostgreSQL and DuckDB.
- **Ways to run the compiler**: a [command line tool](../../../docs/setup/cli.md), a [Rust crate](../../../docs/setup/rust.md), and a [JavaScript package](../../../docs/setup/javascript.md) built to WebAssembly.
- **Introspection**: a query for each dialect that generates the [schema](../../../docs/setup/introspection.md) the compiler needs.
- **Editor support**: syntax highlighting and autocompletion for [CodeMirror 6](../../../docs/setup/codemirror.md).
- **Errors** that say where the problem is and, often, how to fix it. See [errors](../../../docs/errors.md).

## If you installed Querydown from Git

Before this release, you installed Querydown from its Git repository, pinned to a commit. To move to the published packages:

- In Rust, replace the Git dependency on `querydown` with `querydown = "0.1.0"`, and reinstall the command line tool with `cargo install querydown-cli`.
- In JavaScript, replace the `file:` dependencies on `querydown-js` and `querydown-codemirror` with their versions on npm, and drop the step that builds them with `wasm-pack`. The npm package is built for `wasm-pack`'s `web` target, so you call `init()` as before.

These changes, made shortly before this release, break code written against earlier commits:

- A `#table` path now always means _many_ related records. Naming a table that the schema relates by only one record, as in `#issues $#projects`, used to compile, yielding the linking column. It's now an [error](../../../docs/language.md#related-tables-with-single-vs-multiple-records), as the documentation always said it was.
- In JavaScript, every function now throws a [`QuerydownError`](../../../docs/errors.md#javascript), with a kind, a location, and often a hint. Failures used to throw a plain `Error` with only a message (and `introspection_sql` threw a string), and every syntax error had the same message.
- In JavaScript, `compile` now returns an object, so read `result.sql`. It used to return a JSON string for you to parse.
- Strings and quoted identifiers are now raw: a backslash is an ordinary character. For escape sequences, use a [flagged string](../../../docs/language.md#escape-sequences).
- `!` now keeps the rows for which its condition is NULL, so `!status:="open"` includes the issues that have no status.

## What's next

The syntax isn't settled yet, and lots of [functions](../../../docs/functions.md) are still missing. There are no prebuilt binaries of the command line tool yet, so installing it needs a Rust toolchain.
